# First viewport verification

1. Open `EMJ2026.uproject` in UE 5.9. Before changing levels or starting simulation, save any in-flight work using **File > Save All** and inspect the toolbar for active Play/Simulate. Do not discard an existing session.
2. Create **File > New Level > Basic**, then save it as `/Game/Maps/L_AttractionBlockout`. The Basic level supplies lighting and a floor; keep the floor below the board.
3. Open **Window > Content Browser > Content Browser 1**. Enable **Settings > Show C++ Classes** if needed. Find **C++ Classes > EMJ2026 > AttractionSimulation** and drag it into the level. Alternatively use **Window > Place Actors** and search `Attraction Simulation`.
4. In **Window > Outliner**, select `AttractionSimulation`. In **Details > Transform**, set Location to `(0,0,150)`, Rotation `(0,0,0)`, Scale `(1,1,1)`. Leave **Board > Use Demo** checked, **Seed** at `48`, and **Simulation > Running** checked. Six grey spheres should appear; two larger spheres are anchors. Press **F** with the actor selected to frame it. Use a perspective view so labels and height are visible.
5. From the toolbar **Play dropdown > Simulate**, run for 30 seconds. Expected: labels `0 PIN` and `2 PIN` remain fixed; other nodes move; cyan lines show captured spring bonds. Nodes should remain finite without explosive jumps. This is an observation checklist, not a passed test. Record missing visuals, runaway motion or instability as failures.
6. During simulation select the runtime actor in Outliner. **Details > Simulation > Nodes / Tethers** exposes state. Toggle **Running** off to inspect; toggle on to resume. **Reset Simulation** resets the seeded board and clears cuts. Stop only after recording the observations.

# Focused follow-up checks

Disable **Board > Use Demo**, edit **Initial Nodes** and use **Reset Simulation** after changes. Start each case from reset. Position/velocity are local XY in centimeters and centimeters/second; Z is projected to zero at reset. Keep actor scale at one. Runtime array topology should be changed through reset, not by directly editing live Nodes/Tethers.

- **Reciprocity:** Two unpinned nodes at X=-70 and +70, zero velocity, Valence=0, Emit/Receive=(1,0,0) attract. Change both Receive to (-1,0,0) for repulsion. Change only one Receive to (-1,0,0) for directional chasing. Set Drag=0 when checking equal/opposite response in the reciprocal case.
- **Cross-channel:** One node Emit=(1,0,0), Receive=(0,1,0); the other Emit=(0,1,0), Receive=(1,0,0). Identity rows attract reciprocally. Matrix row changes independently control channel interactions.
- **Compatibility:** Field Strength=0, two nodes 150 cm apart, radius=180, Valence=1. Matching default Bond Type=0 forms one spring; mismatched type with no rule forms none. A Max Relative Speed of zero rejects any nonzero relative speed. Both capture radii must admit the distance. First eligible rule wins, and node index order resolves simultaneous capacity competition.
- **Spring/break/slice:** With Field Strength=0, default rest length 140 and separation 150, observe restoring motion. A large outward initial velocity below Max Relative Speed can stretch past Rest Length * (1 + Break Strain), breaking the tether. `SliceTether(index)` is a Blueprint callable API, now also bound to right-drag in the Slice 2 controller. Both cuts and strain breaks suppress that pair until reset. No extra impulse is injected on slicing; existing velocity and changed force balance drive recoil.

Fields are non-contact and spheres have no collision. Overlap is allowed. This is a custom bounded integrator, not Chaos rigid-body simulation; nonreciprocal fields deliberately do not conserve momentum. There are no walls, puzzle objectives, resource budgets or win detection yet.

# Slice 2: Player interaction in PIE

1. With the editor closed, run `./preflight.ps1` from the project root in PowerShell. `-SkipSmokeTest` builds only. An open editor causes a warning and a clean skip. Build and smoke logs are under `Saved/Logs/Preflight*`. Orphaned `UnrealBuildTool.exe` processes are cleared; a process with a live parent, or a dotnet-hosted UBT build, causes failure rather than risking another build. No lock files are deleted. Build/boot timeouts kill only the process tree started by this script.
2. Open the project and save in-flight work via **File > Save All**. Use the Basic level setup above (a floor and lighting help show the grey spheres). Open **Window > World Settings > GameMode > GameMode Override** and select `AttractionGameMode`, or leave it `None` to use the project default. This mode uses `AttractionPlayerController`, no pawn, and a top-down orthographic camera.
3. Keep exactly one `AttractionSimulation` actor in **Window > Outliner**. In **Details > Transform** use location `(0,0,150)`, rotation zero, scale one. If there is no actor, Play creates a temporary demo board at that position. Multiple boards are unsupported; the first actor found receives input.
4. Use **toolbar Play dropdown > Selected Viewport**, then **Play**, rather than Simulate. Click the game viewport to focus it. Expected: a top-down board, cursor ghost sphere, and upper-left control/profile text. **Tab** cycles green Attractor (valence 2), magenta Chaser (valence 1), and yellow Bridge (valence 3, mass 2). All use Bond Type 0 so default springs can attach; the bridge exposes a second field channel for future authored boards.
5. **Left click** an empty spot near the constellation. Expected: one new dynamic grey sphere at the ghost position, node count increases by one, and the node participates in forces/capture. Repeat after changing profile. The safety cap is 128 total nodes, not a puzzle action budget.
6. **Hold right mouse and drag across cyan tethers**. Expected: orange segments follow the swipe and intersected tethers disappear (5 local-cm tolerance). A long gesture is sampled as successive segments; cuts remain suppressed until reset. In **Outliner > runtime AttractionSimulation > Details > Simulation**, Nodes and Tethers expose counts/state. To make the test easier, temporarily uncheck **Running** once tethers exist; inputs still operate while physics is paused.
7. Press **R**. Expected: six seeded demo nodes, previous drops removed, cuts cleared, and springs can recapture on subsequent steps. Running/paused state is preserved. Repeat drop, swipe, reset three times and observe for 30 seconds. Use **Shift+F1** to release the mouse for inspecting Details, and refocus the game viewport before keyboard testing.

These expected outcomes are a manual checklist. Headless editor boot does not run PIE, exercise input, or verify these visuals.
