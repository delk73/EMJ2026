## Repeatable neck stretch and slice checks (scratch level only)

Use the scratch copy from step 7 so the committed gym remains intact. Stop PIE before editing the fixture. Select **Outliner > AttractionSimulation**:

- **Details > Board:** uncheck **Use Demo**; set **Initial Nodes** to two entries. Set positions to `(-100,0,0)` and `(100,0,0)`; both **Pinned=true**, **Valence=1**, **Capture Radius=250**, zero velocity, default coupling.
- **Details > Forces:** set **Field Strength=0**, **Viscosity=0**, **Drag=0**. **Simulation > Running=true**. **Board > Bond Rules:** retain one `0/0` rule with **Rest Length=200**, **Stiffness=0.2**, **Damping=0**, **Break Strain=0.5**, **Max Relative Speed=250**.
- Play: the stationary pair should form a visible neck. Swipe across its midpoint. The tether count should immediately decrease; the visual bridge should pinch/fade within **0.22 simulation seconds**, leaving separated lobes and a briefly visible white swipe. R restores the fixture and reattachment. Overlapping node kernels can remain merged even after a cut; these separated endpoints avoid that ambiguity.
- Stop PIE. Change the second node to **Pinned=false** and **Velocity=(80,0,0)**. Play again: the neck should narrow/fade continuously as separation rises from 200 toward the 300-cm break length; then the bond should disappear. For slow observation, open the PIE console with **~**, enter `slomo 0.2`, close the console, and press R. Restore `slomo 1` when done. The first anchor must remain fixed. Record observations rather than marking a pass from these expectations.

The GPU evaluates the field analytically at native pixel resolution. A **256x3 RGBA32F** texture is a primitive-record table, not an image of the surface: row 0 is node XY/radius/energy, row 1 is tether endpoints, and row 2 is half-width/pinch/0/0. It uses nearest sampling, no sRGB, and no mipmaps; only occupied row spans are uploaded. Counts hide old records after reset/cuts. Rendering supports 256 node records and 256 combined live/cut filament records; live tethers have priority over fading cuts. The existing player cap remains 128 nodes. Larger authored boards can exceed the render cap without changing their physics. GPU cost scales with pixel count and primitive count; check it during the 30-second observation with **PIE console > stat unit / stat gpu**. Compiler/boot checks do not establish GPU performance.

`BoardHalfExtent` still controls drop bounds; physics remains unconstrained. The expanded plane changes the backdrop only. Existing forces, profiles, reset behavior, and zoom controls are retained.

`Scripts/create_liquid_material.py` regenerates the material from `Scripts/LiquidMetaballs.hlsl` and first copies the old asset to `Saved/Backups`. It needs a rendering-enabled Unreal Python commandlet (`-EnablePlugins=PythonScriptPlugin -run=pythonscript -AllowCommandletRendering`, without `-NullRHI`). Runtime does not require Python. The old `T_LiquidDefault` asset is unused and retained; neither runtime nor the new material references it. The new material uses an engine texture as an unsampled zero-count fallback until the runtime float table is assigned.

`Scripts/check_liquid_setup.py` is a lightweight NullRHI Python commandlet check of the saved gym, analytical graph, plane dimensions and native APIs; it never saves the gym and does not test rendering. `python Scripts/check_liquid_gradients.py` checks the analytical partials against independent finite differences, including pinched interiors/caps and coincident endpoints. It verifies equations, not actual GPU output.

# Focused follow-up checks

Disable **Board > Use Demo**, edit **Initial Nodes** and use **Reset Simulation** after changes. Start each case from reset. Position/velocity are local XY in centimeters and centimeters/second; Z is projected to zero at reset. Keep actor scale at one. Runtime array topology should be changed through reset, not by directly editing live Nodes/Tethers.

- **Reciprocity:** Two unpinned nodes at X=-70 and +70, zero velocity, Valence=0, Emit/Receive=(1,0,0) attract. Change both Receive to (-1,0,0) for repulsion. Change only one Receive to (-1,0,0) for directional chasing. Set Drag=0 when checking equal/opposite response in the reciprocal case.
- **Cross-channel:** One node Emit=(1,0,0), Receive=(0,1,0); the other Emit=(0,1,0), Receive=(1,0,0). Identity rows attract reciprocally. Matrix row changes independently control channel interactions.
- **Compatibility:** Field Strength=0, two nodes 150 cm apart, radius=180, Valence=1. Matching default Bond Type=0 forms one spring; mismatched type with no rule forms none. A Max Relative Speed of zero rejects any nonzero relative speed. Both capture radii must admit the distance. First eligible rule wins, and node index order resolves simultaneous capacity competition.
- **Spring/break/slice:** With Field Strength=0, default rest length 140 and separation 150, observe restoring motion. A large outward initial velocity below Max Relative Speed can stretch past Rest Length * (1 + Break Strain), breaking the tether. `SliceTether(index)` is a Blueprint callable API, now also bound to right-drag in the Slice 2 controller. Both cuts and strain breaks suppress that pair until reset. No extra impulse is injected on slicing; existing velocity and changed force balance drive recoil.

Fields are non-contact and spheres have no collision. Overlap is allowed. This is a custom bounded integrator, not Chaos rigid-body simulation; nonreciprocal fields deliberately do not conserve momentum. There are no walls, puzzle objectives, resource budgets or win detection yet.
